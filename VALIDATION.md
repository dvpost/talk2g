## Автоматические проверки

Полный набор запускается командой:

```bash
env GIGA_REAL_MODEL_TESTS=1 GIGA_DESKTOP_TESTS=1 ./check.sh
```

Проверяются: стабилизация меняющейся гипотезы; повторённые слова; временные якоря;
короткое слово рядом с границей подтверждения; принудительная граница окна;
настоящая вставка Unicode в собственное графическое окно; остановка вставки при

inference с поступающим параллельно аудио; настройки и ограничение истории.

событий, ввод текста во время отправки аудио и итог после остановки.

Ruff проверяет исходники, тесты, сквозные проверки и скрипт сборки.
Итоговый полный прогон после добавления двух окон: **121 passed за 61,09 секунды**, включая настоящую модель
и системную вставку; Ruff и проверка форматирования прошли.

[GitHub Actions на коммите 2d1fe4a](https://github.com/dvpost/talk2g/actions/runs/37067524603)

Qt offscreen: проверки настоящего микрофона, системного ввода и модели в этих
запусках пропущены. Linux job устанавливает системные библиотеки Qt/PortAudio;
тесты автозапуска используют переносимые пути и учитывают лимит Windows Run.

## Голосовая остановка

Шестая галочка в настройках и меню трея — «Останавливать по фразе „конец связи“».
Проверены сохранение и синхронизация настройки, команда в одном или нескольких
commit, регистр и пунктуация, ложные совпадения («конец недели», «конец связистам»),
отсутствие остановки на промежуточной гипотезе, выключение во время диктовки,
сохранение обычного слова «конец» после ручной остановки, одно срабатывание,
отсечение оставшегося аудио и сброс состояния для следующей записи.
Отдельный native X11 тест подтверждает, что команда, разделённая между commit,
не попадает в целевое окно, историю и итоговый буфер обмена.

Для сквозной проверки подготовлен файл `benchmarks/voice-stop-input.wav`:
официальный пример GigaAM, пауза, «Конец связи.», три секунды тишины и повтор
исходной речи. Команда синтезирована [Piper](https://github.com/OHF-Voice/piper1-gpl)
с [голосом ru_RU-denis-medium](https://huggingface.co/rhasspy/piper-voices/tree/main/ru/ru_RU/denis/medium)
только для проверки; синтезатор и его модель не входят в приложение.
Исходный файл команды — `benchmarks/voice-command.wav`; скрипт
`benchmarks/make_voice_stop_audio.py` собирает запись и временную разметку.

Результат исходного запуска `voice-stop-source-results.json`: ровно одно
нажатие Ctrl+Shift+A для старта, затем остановка голосом через **0,76 с** после
конца команды. PortAudio/PulseAudio → настоящая GigaAM → XFCE Terminal;
автоматически введённый текст, история и буфер совпали, команда удалена,
первый текст появился до остановки, модель выгружена после завершения.
Задержка зависит от распознавания и настроенной паузы; это измерение конкретной записи.

Обновлённая самостоятельная сборка проверена тем же путём:
`voice-stop-packaged-results.json`, остановка через **0,97 с** после конца
команды, одно нажатие хоткея, точное совпадение ввода/истории/буфера и выгрузка
модели. Отдельно `voice-stop-packaged-launch-results.json` подтверждает запуск
этой сборки через системный `.desktop` с очищенным `LD_LIBRARY_PATH` за **1,91 с**,
скрытое главное окно, отсутствие модели до активации и корректный повторный запуск.
Скрипт сборки автоматически передаёт PyInstaller путь локальных библиотек Qt,
чтобы они попали в готовую папку без ручной настройки окружения.

Воспроизвести проверку:

```bash
uv run python benchmarks/make_voice_stop_audio.py
env LD_LIBRARY_PATH="$PWD/.tools/system-libs/usr/lib/x86_64-linux-gnu" .venv/bin/python benchmarks/e2e_packaged.py --on-demand --terminal --voice-stop --audio benchmarks/voice-stop-input.wav --output benchmarks/voice-stop-source-results.json
```

## Архив эксперимента с двумя окнами

Раздел описывает историческую версию с двумя окнами; режим и скрипт
`benchmarks/compare_windows.py` удалены из текущего приложения.
Галочка «Два окна: быстрый черновик и уточнение» была в настройках и трее,
по умолчанию выключена. Изменение во время записи применяется со следующей
сессии. Одна GigaAM, один вычислитель: короткое окно 5 с для черновика, длинное
16 с для подтверждения; интервалы 0,7 / 2,5 с, удержание свежего хвоста 1,2 с.
При выключенной галочке ruGPT второй экземпляр модели и отдельная языковая
модель не создаются.

Тесты проверяют спорное слово и его исправление до вставки, совпадения по
абсолютному времени, историю коротких окон, повторённые слова, разные размеры
реальных входных аудиоокон, ограничение буфера, границы с перекрытием без
пропусков, последовательность commit, Stop во время длинного inference,
Cancel без ожидания native inference, сохранение/синхронизацию галочки,
отложенное изменение активного режима, отказ старого сервера и оба режима
с настоящей GigaAM. Прежний однопроходный путь сохраняется отдельной веткой.

`benchmarks/compare_windows.py` воспроизводит один и тот же звук в реальном
времени через оба режима одной прогретой модели, сравнивает с ручной разметкой
и сохраняет `benchmarks/dual-window-comparison.json`.
Набор: официальный пример 11,29 с; три синтетические русские записи (техническая
речь, повторы, имена/числа); три повтора официальной записи 33,87 с.
Регистр, пунктуация и ё/е нормализуются; 38 и 25 приводятся к одинаковой форме
с записанными словами. Всего 155 слов с учётом этих преобразований.

| Метрика | Обычный режим | Два окна |
|---|---:|---:|
| Ошибки в словах | 3 / 155 | 4 / 155 |
| WER | 1,94% | 2,58% |
| Медиана времени первого ввода | 1,95 с | 3,98 с |
| Вычисления ASR на весь набор | 15,84 с | 24,67 с |
| Максимальное ожидание результата после Stop | 0,28 с | 0,62 с |

В этом небольшом наборе **улучшение точности не подтверждено**. Дополнительные
вычисления выросли примерно в 1,56 раза, первый ввод отстал примерно на 2 с.
Поэтому режим оставлен экспериментальным, выключенным по умолчанию. Эти
результаты не заменяют проверку на реальном голосе пользователя. WER/CER здесь
не оценивают правильность пунктуации.

Отдельный стресс непрерывной речи использует ту же длинную запись с `silence=2`
для проверки принудительных границ больших окон:

`dual-window-continuous-comparison.json`: оба режима сохранили все 78 слов без
ошибок. В режиме двух окон было 34 коротких и 14 длинных проходов; максимальный
суммарный аудиобуфер с очередью и перекрытием — 18,884 с при ограничении 60 с.
Первый ввод: 1,94 / 4,01 с; хвост после Stop: 0,21 / 0,44 с. Пропусков и
дублирования на принудительных границах длинного окна не обнаружено.

Самостоятельная сборка проверена через Ctrl+Shift+A → виртуальный микрофон
PortAudio/PulseAudio → GigaAM → настоящий XFCE Terminal в режиме двух окон
с загрузкой модели по требованию. `dual-window-packaged-results.json`:
первый ввод через **6,50 с от начала аудио / 7,42 с от хоткея** при холодной
подготовке модели **3,78 с**. Ввод, история и буфер полностью совпали;
первый текст появился до остановки. По фразе «конец связи» запись остановилась
через **0,75 с** после команды, команда удалена, модель выгружена. В логе
зафиксировано 11 быстрых и 6 уточняющих проходов, максимальный буфер 9,92 с.
Логи и личные настройки в Git не включены.

`dual-window-packaged-launch-results.json` проверяет запуск обновлённой
сборки через системную запись автозапуска с чистым окружением: приложение
в трее, модель отсутствует до активации, повторный запуск не создаёт второе окно.

В сквозных проверках микрофон заменён виртуальным monitor-источником PulseAudio,
в который проигрывается настоящая запись. Используется рабочий InputStream
PortAudio и весь путь приложения; исходный источник звука восстанавливается.
Диктовка голосом владельца компьютера пока не измерялась.
Владелец проверил приложение голосом и сообщил о проблемах вставки в терминал
и срабатывания хоткея. После этого обработчик pynput заменён на X11 GrabKey /
Windows RegisterHotKey. Для терминалов используется Ctrl+Shift+V, для обычных
полей Ctrl+V. Вставка ждёт отпускания модификаторов и не посылает искусственных
release/restore для Ctrl/Alt. После завершения очереди вставки весь результат
копируется в буфер. Добавлены тесты разных порядков отпускания клавиш,
автоповтора, занятого хоткея, вставки при удерживаемом хоткее и настоящего терминала.
Дополнительно проверены 16 нажатий хоткея одновременно с очередью из 24 вставок:
все нажатия сработали, весь текст принят. Сочетание вставки отправляется через
XTEST одним пакетом без задержек между клавишами; блокировка X11-сервера
не позволяет другому XTEST-клиенту смешать свои нажатия с этой вставкой.
Новый хоткей по умолчанию — Ctrl+Shift+A. Проверены по четыре активации
в английской и русской раскладках с разными порядками отпускания клавиш
и удержанием для автоповтора, а также 20 быстрых нажатий A при удерживаемых Ctrl/Shift.
Отдельно проверены старт одним нажатием до готовности модели, отмена ожидания,
независимые переключатели трея, их сохранение, скрытие/показ окна во время диктовки,
отключение и повторное включение ввода, сохранение истории при отключённых выходах,
восстановление прежнего текста и HTML буфера после настоящей системной вставки.
Буфер от внешней программы не задерживает старт микрофона: отдельный тест
проверяет запуск менее чем за секунду с владельцем clipboard `xclip`.
Для X11 включён DetectableAutorepeat только на соединении хоткея: это позволяет
различать настоящий отпуск клавиши и автоповтор даже при совпадении временных
отметок в очереди событий. Проверены 20 отдельных нажатий A при удерживаемых
Ctrl/Shift с паузой 4 мс и без паузы, а также подавление повторов при удержании.
Системные настройки клавиатуры не меняются. Использована
[спецификация XKB](https://xorg.freedesktop.org/archive/X11R7.7/doc/kbproto/xkbproto.html).
Терминальная проверка включает режим bracketed paste, используемый приложениями
с текстовым интерфейсом: проверены маркеры вставки и весь текст внутри них.
Задержка графических проверок включает подготовку тестового окна и аудиоустройства.

Для непрерывной речи пример повторён четыре раза без добавления пауз. Проверены
четыре вхождения «лукоморья», непрерывная нумерация commit и совпадение итогового
текста с конкатенацией фрагментов. Это проверка ограниченного буфера и границ окон;
она не является оценкой WER или обещанием идеального распознавания.

Исходные результаты: `benchmarks/model-results.json`, `desktop-results.json`,
`microphone-results.json`, `hotkey-results.json`, `long-stream-results.json`,
`launcher-results.json`, `packaged-results.json`, `terminal-results.json`,
`packaged-terminal-results.json`. JSON содержит реальные тексты,
времена и результат сравнения. Сквозные launcher/packaged проверки используют
отдельный профиль, холодный запуск своего сервера, системную горячую клавишу,
микрофон, вставку в поле, сохранение истории и штатный выход. Они также проверяют,
что сервер приложения прекращает работу после выхода.

На этом CPU медиана декодирования целого примера: CTC 0,46 с, RNNT 0,54 с.
Поэтому CTC выбран по умолчанию. Обе модели загружены в основном проекте;
автономная папка содержит CTC и Silero VAD.

## Загрузка модели по горячей клавише

Четвёртая галочка в трее и настройках — «Загружать модель только при диктовке».
Проверены сохранение настройки, отсутствие запуска ASR при открытии приложения,
переключение на постоянно загруженную модель и обратно, применение режима после
активной диктовки, две последовательные холодные сессии, остановка до готовности
модели и отмена загрузки. Отдельные клиентские тесты сравнивают все отправленные
PCM-сэмплы с исходным аудио, включая начало до готовности сервера, и проверяют,
что накопленный звук не отправляется повторно в реальном темпе. Переполнение
буфера завершает запись с явной ошибкой, а не молча отбрасывает пакеты.

Исходный launcher с настоящим виртуальным микрофоном и XFCE Terminal:
две сессии дали готовность распознавания через **3,13 / 3,03 с от хоткея**,
первый введённый текст через **3,50 / 3,35 с от начала аудио**. За время подготовки
накопилось 2,6 с записи; первые слова сохранились. Каждая сессия запускалась и
завершалась одним нажатием Ctrl+Shift+A, весь итог вводился и копировался.
После Stop свой ASR-сервер действительно отсутствовал, как и до первого хоткея.
Память ASR-процесса во время работы — примерно **553 MiB PSS**;
интерфейс после выгрузки — **163–165 MiB PSS**. Это размер физической памяти
с пропорциональным учётом общих страниц, а не сумма RSS библиотек.
Результаты: `benchmarks/on-demand-launcher-results.json`.

Обновлённая автономная сборка также прошла две холодные диктовки подряд:
готовность через **3,75 / 3,43 с от хоткея**, первый текст через **4,10 / 3,84 с
от начала аудио**. Весь введённый текст и итоговый clipboard совпали с историей;
ASR отсутствовал до активации и после каждой остановки. Память ASR — около
**579 MiB PSS**, GUI после Stop — **206–209 MiB PSS**. Отличие от запуска исходников
включает подготовку окружения автономного процесса. Результаты:
`benchmarks/on-demand-packaged-results.json`.

Остановка через одну секунду аудио, пока автономная модель ещё грузилась:
микрофон закрылся, 1,7 с записи с начальной тишиной остались в очереди,
затем весь распознанный текст был введён и скопирован, ASR выгрузился.
В событии готовности `capturing=false`. Для обрезанной фразы проверяется
сохранение начала и совпадение результата с вводом, а не точность написания:
на столь короткой записи модель ошиблась в слове «Ничьих».
Результаты: `benchmarks/on-demand-early-stop-results.json`.

Контроль постоянно загруженного режима в той же новой автономной сборке:
подготовка сессии **0,44 с от хоткея**, первый текст **2,10 с от начала аудио**,
ввод и clipboard совпали с историей. Результаты:
`benchmarks/warm-packaged-results.json`.

## Управляемый автозапуск

Пятая галочка в настройках и трее — «Запускать при входе в систему».
Проверены установка и удаление записи, повторное включение/отключение,
сохранение остальных приложений в автозапуске, синхронизация галочки с настройками,
ошибка установки и откат при ошибке сохранения настроек. Переключение не
перезапускает ASR. Для Windows проверены операции только над собственным
значением в HKCU Run на контролируемом адаптере реестра, выбор pythonw.exe,
правильное quoting путей и отказ слишком длинной команды до изменения реестра.
Настоящего входа в Windows здесь не было.

На Linux проверка действительно запускает созданный `.desktop` через GIO,
включая пути с пробелами, русскими буквами, кавычками, обратным слешем,
долларом, backtick и `%f`. Не используется shell-парсер вместо desktop-парсера.
Проверка нового входа запускает приложение из временного автозапуска с очищенным
LD_LIBRARY_PATH и другим исходным GIGA_DICTATION_HOME: командный аргумент
выбирает правильный профиль, Qt находит библиотеки, окно остаётся скрытым,
горячая клавиша регистрируется, модель не стартует до активации. Повторный
фоновый запуск не создаёт второй экземпляр и не показывает окно; окно открывается
по запросу, приложение штатно завершает работу, запись удаляется при отключении.
Проверка исходников дала готовность интерфейса через **2,61 с**.
Результаты: `benchmarks/autostart-source-results.json`.
Тот же сценарий автономной сборки прошёл с готовностью интерфейса через
**2,06 с** без настроек окружения разработчика. Результаты:
`benchmarks/autostart-packaged-results.json`.
Установленная запись основного пользовательского профиля отдельно прошла
тот же запуск через GIO с готовностью через **2,62 с**; запись сохранена
включённой, модель по-прежнему загружается по хоткею. Результаты:
`benchmarks/autostart-installed-results.json`.
Дополнительная диктовка новой автономной сборки через Ctrl+Shift+A,
виртуальный микрофон и настоящий XFCE Terminal прошла: начало речи сохранено,
весь ввод и clipboard совпадают с историей, после Stop модель выгружена.
Результаты: `benchmarks/autostart-update-dictation-results.json`.
Рабочая система не перезагружалась: проверен тот же системный запуск из файла,
который рабочая среда использует после входа.

Первичные спецификации:
[XDG Autostart](https://specifications.freedesktop.org/autostart/latest/),
[Desktop Exec](https://specifications.freedesktop.org/desktop-entry/latest/exec-variables.html),
[Windows Run](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys).

## Границы проверки

- Windows: установщик, Unicode SendInput, микрофон, хоткей и запуск сервера
  реализованы; автоматические тесты прошли на Windows runner в GitHub Actions.
  Сквозной прогон с настоящим микрофоном и вводом в приложение на рабочем столе
  Windows пока не проведён.
- Wayland: реализованы RemoteDesktop/GlobalShortcuts/Clipboard, сверены сигнатуры
  с первичной документацией; проверка на настоящем Wayland-композиторе не проведена.
  Доступность порталов и назначение клавиши зависят от среды рабочего стола.
- Буфер обмена и SendInput не дают подтверждения, что произвольное приложение
  приняло символы. Здесь системная вставка проверена на обычном текстовом поле
  и в настоящем XFCE Terminal с отдельным процессом приёма данных.
  Уже введённые слова не удаляются и не исправляются автоматически.

Первичные спецификации Wayland:
[RemoteDesktop](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.RemoteDesktop.html),
[GlobalShortcuts](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.GlobalShortcuts.html),
[Clipboard](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Clipboard.html).
