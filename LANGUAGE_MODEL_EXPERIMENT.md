# Выбор русских гипотез распознавания

Экспериментальная ветка: `experiment/russian-lm-rescoring`. Изменения не входят в `main`.
Проверка выполняется локально на CPU, без отправки диктовки во внешние сервисы.

## Выбор модели

| Кандидат | Назначение | Решение для этого эксперимента |
|---|---|---|
| [ruGPT3-small, SberDevices](https://huggingface.co/ai-forever/rugpt3small_based_on_gpt2) | Русская авторегрессионная языковая модель | Подключена: вероятность обоих текстов вычисляется одним пакетным проходом |
| [ruBERT-tiny2](https://huggingface.co/cointegrated/rubert-tiny2) | Небольшой русский BERT, в основном представления предложений | Сходство представлений само по себе не выбирает правильную транскрипцию; отдельная проверка MLM/PLL не проведена |
| [Vikhr-Llama-3.2-1B-Instruct](https://huggingface.co/Vikhrmodels/Vikhr-Llama-3.2-1B-Instruct) | Инструктивная модель, дообученная на русском датасете | Возможный следующий эксперимент с выбором A/B; её скорость и точность на этом компьютере не измерялись |

Авторы ruGPT описывают обучение русских языковых моделей в
[A Family of Pretrained Transformer Language Models for Russian](https://arxiv.org/abs/2309.10931).
Используется готовая [ONNX INT8-конвертация](https://huggingface.co/onnx-community/rugpt3small_based_on_gpt2-ONNX)
на фиксированном revision `90cff9a5ab6afbf331c6b73516fb7346b9330da2`.
Весовой файл занимает 280 417 320 байт; PyTorch/Transformers для выполнения не нужны.

Пересчёт оценок гипотез ASR языковой моделью — исследованный подход;
[Masked Language Model Scoring](https://arxiv.org/abs/1910.14659) также показывает
применение двунаправленных моделей через последовательное маскирование токенов.
Опубликованные результаты на других моделях и языках не переносятся автоматически
на GigaAM и нашу русскую диктовку.

## Подключённый режим

GigaAM продолжает распознавать короткое и длинное окно. Хранится до 64 коротких
гипотез с абсолютными временами слов. Для ещё не введённого текста формируются
до трёх альтернатив с различающимися словами из этой истории; более ранняя
гипотеза сохраняется, даже если последние два окна одинаково ошиблись.
Вставки/удаления, произвольная генерация и переписывание уже введённого текста
отсутствуют. Подстановки ограничены близкими временами начала/конца.

ruGPT получает одинаковый левый контекст и оценивает среднюю логарифмическую
вероятность токенов каждого кандидата. Контекст исключён из самой оценки;
padding также не учитывается. Всего допускается 256 токенов, из них до 64 —
предыдущий подтверждённый контекст. Решение принимается при разнице не меньше
0.12; при меньшей разнице или превышении бюджета модель воздерживается.
Этот порог не калиброван как вероятность правильного распознавания.

Цифры, набор распространённых числительных, слова с заглавной буквы и некоторые
идентификаторы исключаются эвристиками. Это ограничивает нежелательную замену
редкого имени на распространённое, но не распознаёт все имена, числа и код.
Если оба ASR-прохода не предложили правильное слово, выбрать его невозможно.
При неразрешённом расхождении финал остаётся за длинной гипотезой GigaAM.

Галочка сохраняется независимо от двух окон, доступна только при их включении
и применяется к следующей сессии. ruGPT загружается перед ready только при
активном режиме. В загрузке по хоткею весь серверный процесс с обеими моделями
завершается после диктовки. На этом компьютере веса уже подготовлены.

## Воспроизведение

```bash
./run-linux.sh download --language-model
uv run python benchmarks/score_russian_text.py
uv run python benchmarks/compare_windows.py --with-language-model --output benchmarks/russian-lm-window-comparison.json
env GIGA_REAL_MODEL_TESTS=1 GIGA_LM_TESTS=1 benchmarks/check_x11.sh
```

Контрольные текстовые пары проверяют грамматику и выбор при перестановке A/B.
В паре «Даниил / Данил» оба имени допустимы: предпочтение модели не считается
правильным ответом. Вариант с повторённым словом также показывает пределы
оценки естественности. Эти примеры не являются измерением WER распознавания.
Основной аудиотест использует те же пять публичных/синтетических записей и
ручную разметку, что и прежнее сравнение; результаты сохраняются в JSON.

## Измеренный результат

`benchmarks/russian-lm-window-comparison.json`, 155 слов, одна и та же GigaAM
и те же записи во всех режимах:

| Метрика | Обычный режим | Два окна | Два окна + ruGPT |
|---|---:|---:|---:|
| Ошибки / слова | 3 / 155 | 4 / 155 | 3 / 155 |
| WER | 1,94% | 2,58% | 1,94% |
| Медиана первого ввода | 1,97 с | 4,03 с | 4,05 с |
| Максимум Stop → итог | 0,25 с | 0,83 с | 1,15 с |
| Суммарное время ASR | 16,10 с | 25,39 с | 27,31 с |
| Суммарное время выбора ruGPT | — | — | 2,30 с |

На технической записи ruGPT восстановила ранний вариант «очередь сообщений»
вместо «очередь сообщения». Слово «сервер», распознанное как «сервис», осталось
ошибкой. Модель выполнила 16 этапов выбора: 2 коротких варианта, 12 длинных,
2 отказа. Медиана первого ввода близка к прежнему режиму двух окон, но завершение
стало медленнее, в том числе из-за дополнительного короткого прохода на паузах.

Прирост относительно двух окон — одна исправленная ошибка на небольшом наборе.
Преимущество перед обычным режимом здесь не получено. Пунктуация в WER/CER
нормализуется; реальные пользовательские записи и их ручная разметка отсутствуют.
Поэтому обе экспериментальные галочки оставлены выключенными по умолчанию.

Автономная Linux-сборка также проверена через настоящий глобальный хоткей,
PortAudio/PulseAudio и XFCE Terminal: `benchmarks/russian-lm-packaged-results.json`.
С загрузкой обеих моделей по требованию первый ввод появился через 6,49 с от
хоткея, модели готовы через 5,56 с. Ввод и буфер совпали с историей, остановка
по «конец связи» удалила команду и выгрузила сервер. Сервер с обеими моделями
занимал около 870 MiB PSS; после Stop интерфейс — 206 MiB PSS.
