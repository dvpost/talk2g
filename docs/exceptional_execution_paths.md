Документ текущего состояния по §12
[конвенции 7.1](https://github.com/dvpost/coding_testing_and_docing_conventions/blob/61381814b36fe8c79f75353eedb5de4a6a6a671b/coding_testing_and_docing_conventions.md).
Канонический путь: `docs/exceptional_execution_paths.md`.
Реестр содержит только действующие, явно согласованные исключения.

**Статус проверки реестра: VERIFIED по конвенции 7.1.**

согласием оператора, фактическими условиями, лимитами и тестами.

## EXC-0001 — ожидание готовности модели перед передачей аудио

- **Тип:** RETRY.
- **Статус:** ACTIVE.
- **Область и окружения:** talk2g, клиент диктовки, GET `/health` перед
  единственным WebSocket-подключением. Общий клиентский код Linux/Windows,
  микрофон и файловый ввод; проверено на Linux с реальным WebSocket.
- **Код:** [src/talk2g/client.py](../src/talk2g/client.py) →
  `DictationThread._wait_for_server`, вызывается из `DictationThread.run`;
  HTTP-граница [src/talk2g/service.py](../src/talk2g/service.py) → `health`.
- **Конфигурация / SDK:** `Settings.server_url`, `Settings.load_on_demand`
  в [src/talk2g/config.py](../src/talk2g/config.py). `urllib` GET с
  `timeout=2`, без прокси. Порог ожидания 60 с и пауза 0,05 с заданы
  непосредственно в `_wait_for_server`, отдельной настройки нет.
- **Точка включения:** захват аудио уже запущен, но WebSocket ещё не открыт.
  Для локального запуска по требованию `MainWindow.start_recording` в
  [src/talk2g/desktop.py](../src/talk2g/desktop.py) запускает клиент до
  `LocalService.start`, поэтому первый health может опередить listener.
- **Условия активации:** корректный health с ложным/отсутствующим `ready`
  и без непустого `error`; либо `URLError`, у которого `reason` является
  `ConnectionRefusedError`, только при `load_on_demand=True`, схеме `ws`
  и hostname `127.0.0.1`, `localhost` или `::1`.
- **Условия запрета:** отмена или ошибка захвата; HTTP-ошибка, таймаут,
  другой сетевой сбой, невалидный JSON или чужой app/protocol; отказ
  соединения с удалённым сервером или при выключенном load_on_demand.
  Непустой `error` при неготовой модели прекращает ожидание. При `ready`
  клиент сразу выходит из ожидания.
- **Реальное действие и ограничения:** первый GET и последующие GET идут
  последовательно; число попыток, включая исходную, не фиксировано
  счётчиком, а ограничивается бюджетом времени. После каждой неготовой
  проверки — `cancel_requested.wait(0.05)`, без backoff. При elapsed > 60 с
  возникает ошибка. Проверка порога выполняется после запроса, поэтому
  60 с не являются жёстким общим дедлайном: выполняющийся запрос может
  продлить ожидание; готовый ответ принимается до проверки elapsed.
  `timeout=2` — таймаут сетевых операций urllib, не отдельный общий дедлайн.
- **Конечный результат/отказ:** готовность разрешает однократное подключение
  и передачу накопленного PCM. Истечение бюджета выдаёт
  «Модель не подготовилась за 60 секунд. Проверьте .data/server.log»;
  остальные ошибки передаются через `failure`, захват закрывается.
  Cancel прекращает ожидание после текущего запроса, без подключения;
  Stop закрывает микрофон и сохраняет ожидание для распознавания буфера.
- **Почему необходим сейчас:** при холодном запуске сервер открывает порт
  и загружает модель после начала захвата. Тест холодного хоткея подтверждает
  этот порядок; интеграционные тесты подтверждают сохранение начала речи.
- **Почему недостаточно явной ошибки:** отказ по первой проверке прерывал
  бы штатный запуск по требованию вместо распознавания уже принятой речи.
- **Идемпотентность и побочные эффекты:** повторяется только GET health,
  без перезапуска процесса, повторной отправки PCM или повторного ASR.
  Сессия проверяет один адрес, параллельных readiness-запросов в клиенте нет;
  пауза ограничивает нагрузку примерно 20 запросами/с при быстрых ответах.
  Очередь PCM — 600 пакетов по 100 мс (60 с при стандартном захвате);
  переполнение завершает диктовку с явной ошибкой вместо потери слов.
- **Наблюдаемость:** событие `loading` не чаще смены целой секунды с
  `seconds`, `buffered_audio_seconds`, `capturing`; после handshake событие
  `model_ready` с временем ожидания и объёмом буфера; итоговый отказ —
  сигнал `DictationThread.failure`, отображаемый `MainWindow._failure`.
- **Одобрил оператор:** владелец talk2g, 2026-10-09.
  Идентификатор решения: `TALK2G-DEC-2026-10-09-FLOW-01`, зафиксирован здесь
  по сообщению оператора в текущем диалоге: «FLOW-01 ок, давай дальше».
  Сообщение следует за описанием условий, 60-секундного бюджета с возможным
  превышением на выполняющийся запрос, запретов, Stop и Cancel.
- **Подтверждающие тесты:**
  [tests/test_client.py](../tests/test_client.py) →
  `test_loading_buffers_every_sample_and_sends_backlog_without_replaying`,
  `test_local_on_demand_connection_refusal_waits_for_listener_without_resending_audio`,
  `test_health_failure_stops_capture_without_retry`,
  `test_model_startup_error_stops_capture_without_retry`,
  `test_model_readiness_wait_has_a_finite_deadline`,
  `test_stop_during_loading_closes_capture_but_still_recognizes_buffer`,
  `test_cancel_during_loading_stops_capture_without_waiting_for_model`,
  `test_full_buffer_stops_with_explicit_error_instead_of_dropping_words`;
  [tests/test_desktop_controls.py](../tests/test_desktop_controls.py) →
  `test_cold_hotkey_records_before_readiness_and_unloads_between_sessions`.
- **Условие пересмотра:** изменение порядка запуска/буферизации, health-контракта,
  области серверов, порога ожидания, частоты проверок или требований к отмене.

Периодическое обновление статуса сервера через `MainWindow.check_server`
не входит в EXC-0001: это мониторинг состояния без восстановления операции,
повторной отправки аудио или автоматического перезапуска процесса.

## EXC-0002 — ожидание отпускания модификаторов перед вставкой в X11

- **Тип:** RETRY.
- **Статус:** ACTIVE.
- **Область и окружения:** talk2g, автовставка распознанных фрагментов
  на Linux/X11. На Windows используется Unicode-ввод, на Wayland проверка
  удержания X11 не выполняется; эти пути не покрыты данным разрешением.
- **Код:** [src/talk2g/insertion.py](../src/talk2g/insertion.py) →
  `InsertionQueue._paste` (проверка клавиш и обработка `ModifiersHeld`),
  `_next` (начало бюджета), `_fail` (окончательный отказ);
  [src/talk2g/input.py](../src/talk2g/input.py) → `modifiers_pressed`,
  `x11_paste` (проверка под блокировкой до первого XTEST-события).
- **Конфигурация / SDK:** `Settings.auto_insert` включает системный ввод,
  `Settings.paste_mode` выбирает комбинацию вставки. `QTimer.singleShot`
  с задержкой 30 мс и порог 5 с заданы в `InsertionQueue`, отдельной
  настройки нет. Проверяется маска `ShiftMask | ControlMask | Mod1Mask |
  Mod4Mask | Mod5Mask`; `python-xlib` отправляет один XTEST chord.
- **Точка включения:** `_next` помещает текущий фрагмент в буфер обмена,
  сохраняет `paste_started = time.monotonic()` и планирует `_paste`.
- **Условия активации:** `modifiers_pressed()` подтверждает удержание
  одного из перечисленных модификаторов, либо `x11_paste` выдаёт
  `ModifiersHeld` при повторной проверке под `grab_server`, до ввода.
- **Условия запрета:** приостановленная/пустая очередь; изменившийся или
  непроверяемый целевой фокус; другие ошибки проверки или системного ввода.
  После частичной либо полной отправки клавиш повтор запрещён:
  `ModifiersHeld` возникает только до первого `xtest.fake_input`.
- **Реальное действие и ограничения:** исходная проверка — через 30 мс
  после подготовки буфера; следующие — через `QTimer.singleShot(30, _paste)`,
  без backoff. Число проверок и вызовов `paste`, включая исходный, не
  фиксировано счётчиком: при обнаружении удержания и elapsed > 5 с
  происходит отказ, а не планирование нового повтора. Таймер Qt может
  сработать позднее заданной задержки. Если клавиши уже отпущены,
  вставка разрешается без проверки elapsed; 5 с — порог отказа при
  продолжающемся удержании, не жёсткий дедлайн всего системного ввода.
  На фрагмент допустимо не более одной начатой последовательности XTEST.
- **Конечный результат/отказ:** после отпускания модификаторов выполняется
  однократная вставка текущего фрагмента, затем следующий по порядку.
  При превышении порога с удерживаемыми клавишами либо запрещённой ошибке
  `_fail` приостанавливает очередь и передаёт текущий фрагмент вместе
  с остатком через `failed`; автоматического возобновления нет.
  Распознавание может продолжаться, а невставленный текст сохраняется
  в `MainWindow.remainder` для копирования.
- **Почему необходим сейчас:** пользователь может удерживать модификаторы
  хоткея, пока готов распознанный фрагмент. Native-тест воспроизводит
  зажатый Ctrl+Alt+Space, отсутствие преждевременного ввода и однократную
  вставку после отпускания без повреждения следующего хоткея.
- **Почему недостаточно явной ошибки:** короткое штатное удержание
  горячей клавиши иначе прекращало бы автовставку и требовало ручного
  копирования. Вставка без ожидания передала бы изменённое сочетание
  целевому приложению, которое могло бы не вставить текст.
- **Идемпотентность и побочные эффекты:** во время ожидания только проверка
  состояния X11; фрагмент уже помещён в clipboard. Под блокировкой
  `x11_paste` проверяет фокус и модификаторы перед полным chord,
  освобождает lock в `finally`. Одна очередь обслуживает один фрагмент
  одновременно; проверка фокуса сохраняется на каждой попытке.
  Повтор после ошибки с возможным побочным эффектом запрещён.
- **Наблюдаемость:** ожидание видно через `InsertionQueue.busy` и отсутствие
  вставки; окончательный отказ — сигнал `failed(message, rest)`.
  `MainWindow._insertion_failure` в
  [src/talk2g/desktop.py](../src/talk2g/desktop.py) сохраняет остаток,
  показывает ошибку в основном окне и сообщение «Вставка приостановлена ·
  текст сохраняется» в overlay; пишет warning «Вставка приостановлена»
  с числом оставшихся символов. Отдельной метрики ожидания нет.
- **Одобрил оператор:** владелец talk2g, 2026-10-09.
  Идентификатор решения: `TALK2G-DEC-2026-10-09-FLOW-02`, зафиксирован здесь
  по сообщению «ок согласую» в текущем диалоге. Оно следует за описанием
  FLOW-02 с задержкой 30 мс, порогом 5 с, сохранением остатка, проверкой
  фокуса и запретом повторов после начала ввода, а также примером
  превращения Ctrl+V в Ctrl+Alt+V при удерживаемой горячей клавише.
- **Подтверждающие тесты:**
  [tests/test_insertion.py](../tests/test_insertion.py) →
  `test_held_modifiers_release_before_one_paste`,
  `test_modifier_deadline_preserves_remainder_without_keyboard_input`
  (удержание до вызова и гонка под блокировкой),
  `test_x11_held_modifiers_are_rejected_before_any_keyboard_event`
  (Shift, Ctrl, Alt, Super, AltGr),
  `test_failed_keyboard_input_is_never_retried`,
  `test_unverifiable_x11_focus_does_not_send_keyboard_events`;
  [tests/test_desktop.py](../tests/test_desktop.py) →
  `test_paste_waits_for_hotkey_release_without_corrupting_next_press`,
  `test_hotkey_during_continuous_pasting_never_loses_a_press`,
  `test_changed_window_suspends_insertion_and_preserves_remainder`.
- **Условие пересмотра:** изменение механизма системного ввода, модификаторов,
  проверки фокуса, порога ожидания или точки возникновения `ModifiersHeld`.

## EXC-0003 — продолжение распознавания при файловой ошибке аудиоархива

- **Тип:** DEGRADATION.
- **Статус:** ACTIVE.
- **Область и окружения:** talk2g, необязательное сохранение принятого PCM,
  журнала событий и итоговых метаданных сессии; общий серверный и клиентский
  код Linux/Windows, распознавание целых блоков. Проверено на Linux с реальными
  временными файлами и WebSocket; native Windows не проверен.
- **Код:** [src/talk2g/session_output.py](../src/talk2g/session_output.py) →
  `SessionOutput.__init__` (ошибка создания), `ready`, `_report_recording_error`,
  `append`, `send`, `error`, `close` (уведомления и отсутствие ложного успеха);
  [src/talk2g/recording.py](../src/talk2g/recording.py) →
  `SessionRecording.append`, `event`, `finish`, `_fail`, `_close_files`;
  [src/talk2g/client.py](../src/talk2g/client.py) → `DictationThread.run`
  (приём явного `recording_error` без отказа от ASR).
- **Конфигурация / SDK:** `Settings.save_recordings=True` в
  [src/talk2g/config.py](../src/talk2g/config.py) и согласованный параметр
  `save_recordings` в WebSocket start. Единственный каталог задаётся
  `recordings_directory` как `<project_home>/recordings`; альтернативной
  папки, политики retry или резервного SDK нет.
- **Точка включения:** архив создаётся до ready; PCM записывается при приёме,
  события — при отправке и выполнении ASR; финализация выполняется до
  терминального события либо при очистке отключённого соединения.
- **Условия активации:** `OSError` и его подклассы, включая `PermissionError`,
  при создании каталога/файлов, записи WAV, записи/flush журнала, закрытии
  файлов или публикации `session.json`. В этом случае ошибка относится
  именно к аудиоархиву, а не к модели, микрофону или сетевой передаче.
- **Условия запрета:** сохранение выключено; ошибка другого типа (например,
  `ValueError`); ошибка ASR, протокола или доставки события клиенту.
  При запрошенном архиве отсутствие и `recording_path`, и непустого
  `recording_error` в ready прекращает клиентскую сессию до отправки PCM.
- **Реальное действие и ограничения:** при отказе создания архив не активен;
  при отказе записи/финализации `_fail` фиксирует ошибку, помечает архив
  закрытым и освобождает открытые файлы. Следующие append/event/finish
  не возобновляют запись. Основное распознавание продолжает использовать
  уже принятые данные. Повторов файловой операции после исходной ошибки —
  0, переходов в другой каталог — 0. Закрытие остальных ресурсов после
  ошибки является очисткой; его файловые ошибки журналируются.
  Backoff и бюджет retry — N/A: восстановление архива не выполняется.
- **Конечный результат/отказ:** ошибка создания приходит в ready как
  `recording_error`; ошибка действующего архива приходит один раз как
  `recording` / `status=error`, до следующего события или терминального
  ответа. При разорванном соединении уведомление недоступно, остаётся log.
  Терминальный ответ при ошибке архива не содержит `recording_path`;
  уже выданный при создании путь не является подтверждением сохранения.
  Если ASR успешен, текст возвращается обычными commit/session_end;
  ошибка модели продолжает давать терминальный error.
- **Почему необходим сейчас:** аудио сохраняется для разбора качества ASR,
  а основной результат — распознанный текст. WebSocket-тесты воспроизводят
  отказ прав и заполненный диск при корректно работающем распознавании.
- **Почему недостаточно явной ошибки с остановкой:** отказ необязательного
  архива прервал бы обработку уже записанной, ещё не распознанной речи;
  пользователь потерял бы текст из-за независимой проблемы хранения.
- **Идемпотентность и побочные эффекты:** единственная исходная запись,
  без повторного ASR/PCM, нового каталога или дополнительных попыток
  восстановления. Частичные WAV, журнал, временные/неокончательные
  метаданные могут остаться на диске; пригодность архива не гарантируется.
  Повторная очистка не перезаписывает итог. Архивы используют случайный
  суффикс каталога, права каталога 0700 и файлов 0600 на Linux;
  текст и аудио не включаются в предупреждение о файловой ошибке.
- **Наблюдаемость:** `SessionRecording._fail` пишет warning
  «Не удалось сохранить аудио», включая отказ при отключённом клиенте;
  `SessionOutput.ready` журналирует отказ создания. Клиентское событие
  отображает `MainWindow._event` в
  [src/talk2g/desktop.py](../src/talk2g/desktop.py) → `recording_info`:
  «Не удалось сохранить аудио», и пишет warning. Отдельной метрики нет.
- **Одобрил оператор:** владелец talk2g, 2026-10-09.
  Идентификатор решения: `TALK2G-DEC-2026-10-09-FLOW-03`, зафиксирован здесь
  по сообщению «ок» в текущем диалоге непосредственно после описания
  FLOW-03: продолжать ASR при OSError архива, показать ошибку и записать
  её в log, не повторять запись и не менять папку, не объявлять неполный
  архив сохранённым, допускать частичные файлы, сохранять отказ модели/протокола.
- **Подтверждающие тесты:**
  [tests/test_server.py](../tests/test_server.py) →
  `test_recording_creation_failure_does_not_stop_dictation`,
  `test_recording_write_failure_is_reported_once_and_does_not_stop_dictation`,
  `test_decoder_failure_reaches_client_without_waiting_for_more_audio`,
  `test_invalid_protocol_and_parameters_are_refused`;
  [tests/test_session_output.py](../tests/test_session_output.py) →
  `test_archive_io_error_is_reported_once_without_retry_or_losing_text`
  (PCM, write/flush журнала),
