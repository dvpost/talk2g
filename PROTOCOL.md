# Потоковый протокол v1

`GET /health` возвращает JSON с `app=giga-dictation`, `protocol=1`,
`ready`, `busy`, `model`, `error`. WebSocket: `/v1/dictate`.
Браузерные соединения с Origin отклоняются. Клиент использует duplex-соединение:
передача звука продолжается во время получения результатов.

Первое текстовое сообщение:

```json
{"type":"start","version":1,"rate":16000,"format":"pcm16","session_id":"uuid","token":""}
```

Необязательные параметры: `interval` (0.25–5 с), `holdback` (0.2–3 с),
`silence` (0.2–2 с), `window` (4–24 с). Сервер отвечает `ready` или `error`.
Для экспериментального режима: `dual_window` (boolean, по умолчанию false),
`fast_window` (2–12 с, по умолчанию 5), `quality_window` (4–24 с, по умолчанию 16),
`quality_interval` (0.5–8 с, по умолчанию 2.5), `quality_holdback` (0.2–3 с,
по умолчанию 1.2). Длинное окно должно быть больше короткого. Ответ `ready`
содержит фактический boolean `dual_window`; клиент с включённым режимом отклоняет
сервер, который не подтвердил его поддержку. Версия протокола остаётся 1.
Экспериментальная ветка принимает `lm_rescore` (boolean, по умолчанию false) и
`lm_margin` (0.01–2, по умолчанию 0.12). Режим активен только вместе с двумя
окнами. `ready.lm_rescore` подтверждает фактическую поддержку; клиент отклоняет
старый сервер при включённой галочке. Сервер загружает локальную ruGPT до ready;
при отсутствии весов явно просит предварительно выполнить `download --language-model`.
Далее клиент отправляет бинарные пакеты little-endian signed PCM16, mono,
16000 Hz. Рекомендовано 100 мс, максимум 1 секунда. Максимальная сессия — 2 часа.
Очередь аудио ограничена 60 секундами; при отставании сервер завершает сессию
с понятной ошибкой вместо неограниченного потребления памяти.

События сервера:

```json
{"type":"commit","seq":1,"delta":"Привет","audio_end":0.6,"decode_seconds":0.2}
{"type":"partial","text":"мир","decode_seconds":0.2,"buffer_seconds":2.0}
{"type":"segment_end"}
{"type":"session_end","text":"Привет мир.","audio_seconds":3.0,"elapsed_seconds":3.2}
```

Каждое событие включает исходный `session_id`. `seq` увеличивается на единицу;
`delta` содержит только новый текст со всеми нужными пробелами. Клиент вводит
только commit. Partial может измениться; его следует показывать в виджете.
Повторный seq игнорируется, пропуск останавливает клиента. Итоговый `text`
должен равняться конкатенации delta. Повторно вводить его не нужно.

При двух окнах partial содержит `source=fast` или `source=quality`, абсолютные
`audio_start` и `audio_end`. Commit получает `source=quality` и сохраняет прежние
гарантии последовательности. Короткие гипотезы показываются без вставки;
слова длинной гипотезы подтверждаются по совпадению нормализованного текста и
времени с последней короткой гипотезой, покрывающей соответствующий участок аудио.
На паузе принимается итог длинного окна; на принудительной границе сохраняется
неподтверждённый хвост с перекрытием. Session_end дополнительно содержит объект
`dual_window`: `fast_decodes`, `quality_decodes`, `decode_seconds`,
`max_buffer_seconds`, `disagreements`. Последний счётчик означает число проходов
с неподтверждённым префиксом, включая отсутствие покрытия; это не WER и не
вероятность ошибки. Загрузка модели и формат PCM не меняются.

При `lm_rescore=true` перед commit оцениваются до трёх разных вариантов из
истории коротких окон. Подстановка допускается при разнице начала не более
0.2 с и конца не более 0.25 с. Имена по регистру, цифры/часть числительных и
идентификаторы исключены эвристикой. Модель сравнивает средний log probability
токенов кандидата при одинаковом левом контексте; `lm_margin` — разница этой
оценки, не вероятность правильности. Общий лимит — 256 токенов, включая BOS
и до 64 токенов подтверждённого контекста. Слишком длинные кандидаты вызывают отказ.

Событие `rescore` содержит `choice=short|long|abstain`, `scores` последней пары,
`seconds` суммы сравнений, `evaluated`, `substitutions`, `protected`, `reason`.
Тексты кандидатов в него не включаются. При выборе короткого варианта слова
сохраняют временные якоря длинного окна; уже вставленные слова защищаются при
повторном распознавании перекрытия. Нерешённые расхождения ждут дальнейшего звука;
на паузе/Stop для них остаётся итог GigaAM длинного окна. При уверенном выборе
ruGPT итог может содержать слова короткого окна и на паузе.
`dual_window.language_model` содержит `comparisons`, `short_choices`,
`long_choices`, `abstentions`, `seconds`; `comparisons` считает этапы выбора,
каждый из которых может выполнять до трёх сравнений. Старый `disagreements`
используется в режиме без языковой модели. Commit сохраняет `source=quality`,
поскольку его выдаёт этап подтверждения, включая возможные подстановки ruGPT.

После отправки всех аудиопакетов клиент отправляет `{"type":"stop"}`.
Сервер распознаёт последний неполный кадр, выдаёт оставшиеся commit и session_end.
`{"type":"cancel"}` отбрасывает непроверенный хвост, возвращая cancelled
с уже подтверждённым текстом. Разрыв соединения освобождает сервер.
Автоматический повтор аудио после разрыва не выполняется: системная вставка
не предоставляет транзакции, и повтор мог бы напечатать текст второй раз.

Подтверждение слова использует совпадение в двух гипотезах, позицию слова по времени
и удержание свежего хвоста. На границах окон последние подтверждённые слова служат
якорями с проверкой времени, поэтому повторённые в речи слова сохраняются.
Это эвристическая стабилизация пакетной модели; она не гарантирует безошибочное
распознавание или неизменность будущих гипотез. Для ввода принято решение
сохранять подтверждённый текст, избегая удаления пользовательских символов.
