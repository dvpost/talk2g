# Giga Dictation

Локальная голосовая диктовка по-русски на **GigaAM v3** для Linux и Windows.
Слова появляются в выбранном приложении **во время речи**. Можно держать модель
в памяти постоянно или загружать только на время диктовки. После остановки
обрабатывается оставшийся хвост записи. Интернет и аккаунт Сбера для диктовки не нужны.

Исходники: [dvpost/talk2g](https://github.com/dvpost/talk2g). Для нового компьютера:

```bash
git clone https://github.com/dvpost/talk2g.git
cd talk2g
./run-linux.sh
```

Первый запуск устанавливает окружение и скачивает веса. Для Windows используйте
`run-windows.cmd`. Локальные настройки, история диктовок, логи и веса в Git не входят.

## Запуск на этом компьютере

```bash
/home/vm/pet_project/giga-dictation/run-linux.sh
```

Окружение и модели уже загружены. Дождитесь «Готово», поставьте курсор
в нужное поле и нажмите **Ctrl+Shift+A** (та же физическая клавиша в русской раскладке).
Говорите; текст начнёт вводиться через
несколько секунд. Повторное нажатие завершает диктовку и вводит её остаток.
Плавающий виджет показывает последние распознанные слова и сохраняет фокус
в целевом приложении. Главное окно можно закрыть в системный трей.
«Выход» в меню трея завершает приложение и запущенный им сервер.

При смене активного окна на Windows/X11 автоматическая вставка приостанавливается.
Весь текст остаётся в истории, а кнопка «Скопировать невведённый остаток» позволяет
вставить оставшуюся часть вручную. Можно отключить автоматический ввод в настройках.
История сохраняет последние 100 диктовок; её можно очистить в приложении.
После остановки **весь текст диктовки** автоматически копируется в буфер обмена.
Это можно отключить в настройках. Режим вставки Linux определяется автоматически:
Ctrl+Shift+V для терминала и Ctrl+V для обычного поля. При необходимости выберите
своё сочетание в настройках («Вставка в Linux»).

По **правой кнопке на значке «Г» в трее** доступны переключатели:
автоматический ввод, копирование диктовки в буфер, синее окно диктовки и
**«Загружать модель только при диктовке»**, **«Запускать при входе в систему»** и
**«Останавливать по фразе „конец связи“»**, **«Два окна: быстрый черновик и уточнение»**,
а в экспериментальной ветке — **«Выбирать варианты двух окон с помощью ruGPT»**.
Настройки сохраняются между запусками. Если автоматический ввод
отключён, текст продолжает распознаваться и сохраняться в истории. Если копирование
отключено, прежнее содержимое буфера после диктовки сохраняется, включая форматированный
текст. Повторное включение ввода во время диктовки вводит следующие слова в текущее окно;
ранее пропущенную часть можно скопировать из истории.

Галочка **«Останавливать по фразе „конец связи“»** также есть в настройках.
При включённом режиме произнесите **«конец связи»** и сделайте короткую паузу:
подтверждённая команда завершает запись тем же способом, что и повторное
нажатие Ctrl+Shift+A. Команда и речь после неё исключаются из ввода, истории и
буфера обмена; текст перед командой сохраняется. Регистр и пунктуация не мешают,
команда может прийти в разных фрагментах. Промежуточные гипотезы не останавливают
запись. Если фраза распознана с ошибкой, используйте хоткей. При выключенной
галочке эти слова вводятся как обычный текст. Настройку можно менять во время
диктовки; для нового профиля она по умолчанию выключена.

Галочка **«Два окна: быстрый черновик и уточнение»** включает экспериментальный режим.
Быстрое окно до **5 секунд** обновляется примерно каждые **0,7 секунды** и показывает
черновик. Уточняющее окно до **16 секунд** распознаётся примерно раз в **2,5 секунды**,
а на паузе и остановке — сразу. Начинать говорить можно сразу: ждать заполнения
большого окна не нужно. Оба прохода используют одну загруженную GigaAM и выполняются
по очереди, без накопления запросов распознавания.

Вводятся только слова уточняющего прохода, согласованные с быстрыми гипотезами по
тексту и времени. Свежий хвост удерживается примерно на **1,2 секунды**; спорный
участок остаётся в черновике. На паузе принимается уточнённый вариант. При достижении
границы большого окна подтверждается его безопасное начало, а хвост переносится
с перекрытием. Уже введённый текст не переписывается. Это проверка устойчивости,
а не гарантия правильности: оба прохода могут ошибаться одинаково.

Режим может увеличить задержку ввода и нагрузку CPU. Галочка сохраняется; изменение
во время записи действует со следующей диктовки и не перезапускает микрофон.
Для новых профилей режим выключен. Снятие галочки возвращает прежний алгоритм.
В `.data/settings.json` доступны `fast_window`, `quality_window`, `quality_interval`
и `quality_holdback`; для них проверяются диапазоны, длинное окно должно быть больше
короткого. Для удалённого сервера нужна обновлённая версия с поддержкой двух окон.

Сравнение режимов на одних и тех же публичных/синтетических записях:

```bash
uv run python benchmarks/compare_windows.py
```

Скрипт измеряет ошибки в словах (WER), ошибки в символах (CER), время первого
черновика и ввода, время завершения, длительность вычислений и размер буфера.
Результат: `benchmarks/dual-window-comparison.json`. Разметка и записи входят в
`tests/fixtures`; реальные личные диктовки в этот набор не включаются.

На текущем небольшом наборе **улучшение точности не подтверждено**: обычный режим
дал 3 ошибки на 155 слов, два окна — 4. Медиана первого ввода выросла с 1,95 до
3,98 с; вычислений стало больше примерно в 1,56 раза. Поэтому режим оставлен
выключенным по умолчанию. Подробные результаты — [VALIDATION.md](VALIDATION.md).

Галочка **«Загружать модель только при диктовке»** также есть в настройках:

- **Включена:** хоткей сразу открывает микрофон; пока модель загружается, звук
  накапливается в памяти. Затем накопленные пакеты отправляются без ожидания,
  и распознавание догоняет речь. После Stop и обработки хвоста собственный
  процесс сервера завершается и освобождает память модели.
- **Выключена:** модель загружается при открытии приложения и остаётся в памяти.
  Это уменьшает задержку первых слов; в простое распознавание не выполняется.

Режим сохраняется сразу. Переключение во время диктовки применяется после её
завершения. На вкладке «Диктовка» показаны время подготовки от нажатия хоткея
и длительность накопленного звука. Можно остановить запись, пока модель грузится:
уже записанное аудио всё равно будет распознано. «Прервать» отменяет ожидание.
Буфер ограничен 60 секундами (около 1,9 МБ PCM); при переполнении приложение
явно сообщает об ошибке. Загрузите веса через установщик до проверки этого режима.
В основном профиле на этом компьютере режим включён для эксперимента;
для нового профиля по умолчанию модель остаётся загруженной.

Галочка **«Запускать при входе в систему»** устанавливает автозапуск для текущего
пользователя; снятие галочки удаляет эту запись. Доступна в настройках и трее,
применяется сразу и не прерывает текущую диктовку. После входа приложение
запускается в трее. Если трея нет, открывается главное окно. Повторный запуск
в фоне не создаёт второй экземпляр и не открывает окно поверх других программ.
Выбранный режим загрузки модели сохраняется: если модель загружается по хоткею,
она не занимает память сразу после входа. «Выход» закрывает текущий процесс,
оставляя автозапуск на следующий вход; выключить его можно галочкой.

Linux использует `~/.config/autostart/giga-dictation.desktop` (или каталог
`$XDG_CONFIG_HOME`); Windows — запись `GigaDictation` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`.
Права администратора не нужны. Автозапуск привязан к абсолютному пути программы
и её профиля. После переноса папки выключите и снова включите галочку из нового
расположения. Для нового профиля автозапуск по умолчанию выключен;
состояние галочки при открытии программы проверяется по системной записи.
Ручной запуск в трее: `./run-linux.sh app --background`.

## Эксперимент: выбор вариантов русской языковой моделью

В экспериментальной ветке `experiment/russian-lm-rescoring` добавлена галочка
**«Выбирать варианты двух окон с помощью ruGPT»** в настройках и трее.
Она доступна при включённых двух окнах и применяется со следующей диктовки.
ruGPT3-small INT8 оценивает варианты спорных слов в контексте уже введённого
текста; может выбрать короткое или длинное окно, либо отказаться от уверенного
выбора. Сохраняются также ранние гипотезы короткого окна. Выбор и время оценки
показываются в статусе приложения. При выключенной галочке действует прежний режим.

Однократная подготовка на новой машине:

```bash
./run-linux.sh download --language-model
```

На Windows: `run-windows.cmd download --language-model`. Дополнительно скачивается
около 280 МБ весов. На этом компьютере они уже скачаны. Текст оценивается локально,
без PyTorch и внешнего API; используется ONNX Runtime CPU. При загрузке по хоткею
ruGPT находится в том же серверном процессе и выгружается вместе с GigaAM.

Это ограниченный эксперимент: заменяются только существующие варианты слов,
совпадающие по времени. Вставки/удаления слов языковая модель не выполняет.
Цифры, распространённые числительные, слова с заглавной буквы и некоторые
идентификаторы исключены из замен. Эти эвристики не распознают все имена и код.
Вероятность естественного текста не подтверждает, что именно он был произнесён.
Исследование и ограничения — [LANGUAGE_MODEL_EXPERIMENT.md](LANGUAGE_MODEL_EXPERIMENT.md).

## Установка на другую машину

**Linux x86_64, Python 3.12.** Скопируйте папку проекта, выполните `./setup-linux.sh`,
затем `./run-linux.sh`. Установщик использует uv и закреплённые зависимости;
если Python отсутствует, uv скачает его. Для микрофона нужна системная PortAudio,
для вставки в X11 — xdotool. На Debian/Ubuntu обычная команда установки:

```bash
sudo apt install libportaudio2 xdotool libxcb-cursor0
```

Если отсутствует только `libxcb-cursor0`, установщик Debian/Ubuntu скачает
библиотеку внутрь проекта без sudo. Прочие библиотеки Qt должны быть доступны
в системе с графическим рабочим столом. Диктовка использует mono 16 kHz;
выбирайте системное устройство `default`/`pipewire`, если аппаратное устройство
не поддерживает такую частоту.

**Windows 10/11 x64.** Скопируйте проект и дважды нажмите `run-windows.cmd`.
При первом запуске он вызовет `setup-windows.ps1`: скачает uv, Python 3.12,
зависимости и недостающие веса. Отдельная `.venv-win` не пересекается с Linux.
Разрешите доступ к микрофону настольным приложениям в настройках Windows.
Ввод использует Unicode SendInput и работает с русской раскладкой и латинской.
Целевое приложение должно иметь тот же уровень прав, что и диктовщик.

**Wayland.** Откройте настройки приложения и нажмите «Разрешить ввод и хоткей
Wayland». Приложение обращается к системным порталам RemoteDesktop,
GlobalShortcuts и Clipboard; доступность зависит от среды рабочего стола.
Если Clipboard недоступен, нужен пакет `wl-clipboard`. Если нет GlobalShortcuts,
назначьте в настройках Linux свою клавишу на абсолютный путь `run-linux.sh toggle`.
Во время диктовки оставляйте фокус в целевом поле: портал не предоставляет
универсальную проверку активного окна. Если среда не разрешает ввод через портал,
отключите автоматическую вставку и копируйте распознанный текст из приложения.

**Проверено здесь:** Linux X11, настоящий путь захвата PortAudio/PipeWire,
потоковая GigaAM и вставка в графическое поле. Windows и Wayland реализованы,
но на их реальном рабочем столе пока не проверены. Подробности — [VALIDATION.md](VALIDATION.md).

## Скорость и принцип работы

По умолчанию используется **GigaAM v3 E2E CTC INT8 на CPU**, четыре потока.
Silero VAD обнаруживает речь и паузы. Каждые примерно 0,7 секунды сервер распознаёт
текущее окно. Слова, одинаковые в двух последовательных гипотезах, подтверждаются
и добавляются в поле ввода. Последнее слово и примерно 0,8 секунды свежего звука
остаются на уточнение; при паузе 0,6 секунды хвост подтверждается целиком.

Окно ограничено 10 секундами. При непрерывной речи оно сдвигается с перекрытием,
а подтверждённое начало удаляется из буфера. Это последовательное распознавание
коротких окон, а не встроенный streaming API GigaAM. Уже введённый текст
не переписывается; ошибки модели можно исправить после остановки.
Длинная речь не требует повторного распознавания всей записи после Stop.

На этой виртуальной машине первые слова вставились через 2,6 секунды при
воспроизведении файла и через 3,1 секунды через виртуальный микрофон. Эти значения
относятся к конкретной записи и компьютеру. Результаты и исходные события находятся
в [benchmarks](benchmarks); качество зависит от голоса, шума и микрофона.

В настройках можно изменить микрофон, хоткей, адрес сервера, интервал и паузу.
Дополнительные параметры находятся в `.data/settings.json`: `holdback`, `window`,
`threads`, `model`. Для альтернативной RNNT-модели:

```bash
./run-linux.sh download --model gigaam-v3-e2e-rnnt
./run-linux.sh server --model gigaam-v3-e2e-rnnt
```

Чтобы приложение автоматически запускало RNNT, завершите его, установите
`"model": "gigaam-v3-e2e-rnnt"` в настройках и запустите снова. При существующем
сервере фактическая модель определяется этим сервером.

## Фоновый или удалённый сервер

Сервер стартует автоматически с интерфейсом или по хоткею, в зависимости от
галочки загрузки модели. Отдельный запуск полезен, если нужно держать модель
загруженной независимо от окна:

```bash
./run-linux.sh server
./run-linux.sh doctor
./run-linux.sh transcribe tests/fixtures/example.wav
./run-linux.sh replay tests/fixtures/example.wav --events benchmarks/replay-events.json
```

Для Windows заменяйте `./run-linux.sh` на `run-windows.cmd`.
`doctor` показывает аудиоустройства и зависимости. `/health` сообщает готовность.
Интерфейс подключается к `ws://127.0.0.1:8769/v1/dictate` и может использовать
уже работающий экземпляр сервера. Одновременно разрешена одна диктовка.
Галочка управляет жизнью только локального сервера, запущенного самим приложением;
уже работающий отдельный или удалённый сервер клиент не выгружает.

Для сетевого сервера задайте `GIGA_DICTATION_TOKEN` перед запуском с
`--host 0.0.0.0`, укажите такой же токен в интерфейсе клиента. В недоверенной сети
используйте `wss://` через TLS-прокси. Протокол описан в [PROTOCOL.md](PROTOCOL.md).

Все настройки, история и журналы `app.log`/`server.log` расположены в `.data` внутри проекта.
Весовые файлы находятся в `models`. Аудио с микрофона не сохраняется на диск;
после завершения буфер обмена содержит весь распознанный текст.
Каталог можно переопределить переменной `GIGA_DICTATION_HOME`.

## Разработка и воспроизводимые проверки

```bash
uv sync --frozen --extra desktop --extra dev
./check.sh
env GIGA_DESKTOP_TESTS=1 ./check.sh
env GIGA_REAL_MODEL_TESTS=1 ./check.sh
```

Обычные тесты используют проверяемый WebSocket-сервер и контролируемое
распознавание. Проверки `desktop` печатают только в собственные тестовые окна.
Проверки `real_model` запускают настоящую GigaAM; веса должны быть скачаны.

```bash
./run-linux.sh server
uv run python benchmarks/e2e_desktop.py
uv run python benchmarks/e2e_desktop.py --microphone-pulse --output benchmarks/microphone-results.json
uv run python benchmarks/long_stream.py
uv run python benchmarks/e2e_packaged.py --on-demand --terminal --sessions 2 --output benchmarks/on-demand-launcher-results.json
```

Для этих графических проверок на машине без системной `libxcb-cursor0`
добавьте `LD_LIBRARY_PATH="$PWD/.tools/system-libs/usr/lib/x86_64-linux-gnu"`.
`--microphone-pulse` временно создаёт виртуальный микрофон и восстанавливает
исходный источник звука при завершении. Проверку запускайте отдельно от других
программ, записывающих звук. На Windows тест через файл также доступен.

Автономная папка без установленного Python собирается **на целевой ОС**:

```bash
uv run python packaging/build.py
```

Результат — `dist/GigaDictation`, включая CTC и VAD. Такая папка уже собрана здесь
для Linux x86_64 / Ubuntu 24.04 (glibc 2.39 или новее). На Linux запускайте
`dist/GigaDictation/GigaDictation`, на Windows — `GigaDictation.exe`.
Переносите папку целиком. Системные требования Linux к PortAudio/xdotool остаются.
Qt-библиотеки остаются отдельными файлами.

Сквозная проверка самого запускающего файла и автономной сборки:

```bash
uv run python benchmarks/e2e_packaged.py
uv run python benchmarks/e2e_packaged.py --executable dist/GigaDictation/GigaDictation --output benchmarks/packaged-results.json
```

Эти проверки создают отдельный временный профиль, используют глобальный хоткей,
виртуальный микрофон, проверяют вставку и историю и завершают свой сервер.
Проверка `autostart_smoke.py` создаёт временную запись автозапуска и действительно
запускает её через системный launcher GIO с окружением нового входа. Проверяет
запуск в трее, нужный профиль, отсутствие второй копии, открытие окна по запросу
и удаление записи при отключении. Обычное приложение перед проверкой нужно завершить.
